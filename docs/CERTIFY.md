# 一次体检的标准流程（live 认证）

> 对应 `PLAN.md §10.19` M1.1「固化 live 认证流程：可复跑题单 + 参数表 + 预期，跑一轮干净双平台认证」。
> 这是三层验证的**第三层**（真网络）：上两层 = `python -m harness.test`（确定性回归）+ 黄金回放（evalgold）。
> 目的：在**固定题单 + 固定参数**下跑一轮真爬，产出可复跑的认证报告，并过确定性 verifier。
> **认准本文走**——换题单或改参数 = 换一轮新认证，新旧报告不可比。

注意：calibrate 自带 18770/18771 守卫（全挂即拒跑），但 **18772 不在守卫里，得手工确认**。

### 2. 打分服务会不会中途被杀（2026-09-10 实测踩到）

演示服务器 上跑本地小模型的 `nlp-tool` **会被系统内存回收杀掉**（演示服务器 无交换分区，一有尖峰就杀）。
杀了会自动重启，但重载模型要 6~13 秒，**这段窗口里我们的请求断连 → 该批样本降级成关键词兜底**。

- 起跑前记下重启计数：`ssh <your-server> "systemctl show nlp-tool -p NRestarts"`；
- 跑完再查一次，**计数涨了 = 本轮有题撞上重启窗口**，对照日志里 `[measure] ... 度量降级 keyword` 定位是哪题，**该题重跑**；
- 想跑中盯：`watch -n 60 'systemctl show nlp-tool -p NRestarts -p ActiveEnterTimestamp'`。

2026-09-10 实测：一天内两次被杀（14:03:53 / 15:12:07），分别砸中第一批第 2 题、第二批第 3 题。
**这是 演示服务器 的环境问题，不是 harness 的 bug**；根治要动服务器（加交换分区 / 查服务内存泄漏 / 调内存回收优先级），需另行拍板。

### 3. 三个环境变量（不设 = 静默降级，体检作废）

```
NLP_TOOL_URL=http://127.0.0.1:18772
NLP_TOOL_TOKEN_FILE=<演示服务器 上 .tool_token 的本地副本路径>
DEEPSEEK_API_KEY=<存在即可>
```

- `DEEPSEEK_API_KEY` 来自环境变量，**或者**用户在页面上填（后者落在**本机** `secrets.json`，与 `settings.json` 分开存）。
  两种来源都只看「有没有值」这一件事；**明文永不回传前端**，也**不写进 `settings.json`**（凭证纪律）。
- 怎么判生效：跑起来日志里**不该**出现下面任一句；出现了就是这轮软信号是假的，重设再跑：
  - `[measure] tool ... 度量降级 keyword`

### 分三批怎么跑（14 题 = 5 + 5 + 4）

一次跑一批、每批一个进程：批间天然隔开（风控喘口气，也方便中途查报告）。脚本 `_tmp/cert14_batch.ps1`
把「设 env → 睡批间 → 跑这批」封在一起：

```
powershell -File _tmp\cert14_batch.ps1 -Batch 1                    # Q1-Q5   (--start 0  --max-q 5)
powershell -File _tmp\cert14_batch.ps1 -Batch 2 -GapBefore 1800    # Q6-Q10  (--start 5  --max-q 5)
powershell -File _tmp\cert14_batch.ps1 -Batch 3 -GapBefore 1800    # Q11-Q14 (--start 10 --max-q 4)
```

**间隔 = 批内 11 个 10 分钟（4+4+3）+ 批间 2 个 30 分钟。** 中途单题补跑仍用 `--start N --max-q 1`（N = 0 基全局序号）。

起跑前先冒烟（同一份题单，只验流程不触网）：

```
python -m harness.runner.calibrate --mock --qsfile harness/data/cert_qs.tsv --max-q 1 --interval 0 ^
    --db _tmp/smoke_v3.db --report _tmp/smoke_v3.txt --tag smoke-v3
```

**预计总时长**：14 题 ×（单题约 8–10 分钟）+ 11 × 10 分钟批内 + 2 × 30 分钟批间 ≈ **4.5–5.5 小时**。

跑批期间可另开 `python -m harness.runner.observe --db harness/data/cert_<日期>.db` 看中间态（只读）。

## 四、跑完怎么判

### 判据 1：收口与错误 —— 看报告
`_tmp/cert_report_<日期>.txt` 里每题「结论行」非空、非 `(未收口)`，且**无** `!! 题失败`。

### 判据 2：引用与结论 —— 跑 verifier（确定性，不烧模型）

```
1..14 | ForEach-Object {
  python -m harness.runner.verify --db harness/data/cert_<日期>.db `
      --scope "exp:calib:cert-<日期>:q$_" --detail
}
```

每题要 `OK=1 FLAG=0`。**hard≠0 直接判不过**：

| FLAG | 含义 |
|---|---|
| `cite_unresolved` | 编造引用（引了库里没有的 id） |
| `cite_cross_scope` | 跨题串引用（scope 隔离漏了） |
| `concl_missing` | 没干净收口 |

### 判据 3：软信号是真模型（否则整轮作废）

**先看日志（最快）**：报告里每题那段不得出现
`[measure] nlp-tool 请求失败 ... 度量降级 keyword`。
出现即**该题作废重跑**——注意这个警告**每个进程只打印一次**（后续同类失败被静默），
所以它出现 = 至少有一批样本走了关键词兜底。

**再拆批次（聚合会骗人）**：光看整题聚合**抓不到「只有部分批次掉线」的情形**。
2026-09-10 第 2 题实测：234 条里 66 条兜底，聚合仍显示「不一致 15 条」看似正常，
但按爬取批次拆就露馅——某批（crawl#12，整批 66 条）**100% 与关键词表同值** = 那一批是兜底。

所以按附录 B 的脚本跑，逐题、逐批次看：

- 某个**批次条数 ≥ 20** 且 `senti/sarcasm` 与关键词表**全同** → 该批兜底，此题作废重跑；
- 批次条数 < 20 时「全同」不足以判定（小批次偶然撞值很正常，2026-09-10 实测踩过两次误报：
  2 条批 / 1 条批 / 5 条批都曾全同但服务正常），单独列出观察，别当通过也别当兜底；
  同轮若日志无降级警告，基本可排除兜底（警告只要出过一次就会打，没打 = 没降级）；
- 各批次都**有不一致**（= 被小模型/judge 覆写的那些），且总数 ≈ 日志「可疑 N 条超导流上限」= 真模型。

> **已知盲区**：`measure.py` 的降级警告每次进程只打印一次（`_warned` 去重），
> 所以日志里只出现 1 条失败 ≠ 只失败 1 次；后续同类失败是静默的。判「有没有兜底」以**逐批次拆解**为准，日志只作辅助。

### 判据 4：硬尾纪律（determiner）

对题单里的硬尾题（反串/自基线/黑话），答案要么 ≥1 个 `[id=N]`，要么明说判不了/证据不足；
**零引用还下断言 = 违规**。判据复用 `_tmp/verify_determiner_discipline.py` 的 `disciplined()`
（措辞镜像 evalgold，防口径漂移）。

### 观察项（不判过不过，但要写进报告）

- **双平台**：每题报告行「平台新增」应 NGA>0 且 bili>0。某平台为 0，要写清是「检索口径没覆盖」
  （如 NGA 版内标题搜对长词命不中）还是「爬虫失败」——别含糊。
- **护栏**：`in/out` 与 `rounds` 记进报告，看有没有异常风暴。

### 顺手：数据层只增

```
python -m harness.guard      # 期望 0 违规
```

## 附录 B：软信号真伪对照脚本（判据 3 用）

原理：关键词兜底和真模型都产出 0/1/2，光看分布分不出；但**兜底的产出必然和关键词表逐条一致**，
对不上就说明有模型/judge 覆写。**必须按爬取批次拆**——整题聚合会漏掉"只有一批掉线"的情形。

```python
# 用法: python check_softsignal.py <标定库.db>
import sqlite3, sys
from collections import defaultdict
db = sys.argv[1]
c = sqlite3.connect(db)
MARK = ["岁月史书","孝","经典","赢","绷","谢","回旋镖","典","尽孝","贴金","结晶孝子","韭菜","捂嘴","洗地"]
NEG  = ["烂","答辩","恶心","退坑","拉胯","坑","垃圾","失望","离谱","踩死"]
POS  = ["真香","顶","强","爽","好玩","推荐","优秀","好评"]

def kw_sarc(t):    return 1 if any(m in t for m in MARK) else 0
def kw_senti(t):
    n = sum(t.count(w) for w in NEG); p = sum(t.count(w) for w in POS)
    return 0 if n > p else (2 if p > n else 1)

rows = list(c.execute("""select o.scope,o.crawl_id,cr.platform,o.title,o.text,o.senti_arg,o.sarcasm
                         from observation o join crawl_run cr on o.crawl_id=cr.id
                         order by o.scope,o.crawl_id,o.id"""))
by = defaultdict(list)
for sc, cid, plat, ti, tx, sa, sc2 in rows:
    by[(sc, cid, plat)].append((sa, sc2, kw_senti((ti or "")+(tx or "")), kw_sarc((ti or "")+(tx or ""))))

bad = 0
for (sc, cid, plat), rs in sorted(by.items()):
    n = len(rs)
    ss = sum(1 for sa,s2,kse,ksc in rs if sa == kse)   # senti 与关键词同
    cs = sum(1 for sa,s2,kse,ksc in rs if s2 == ksc)   # sarcasm 与关键词同
    fallback = (ss == n and cs == n)                    # 整批同值
    small = n < 20                                      # 小批次: 同值不足以判定(实测误报)
    bad += fallback and not small
    print("%s crawl#%-4s %-9s n=%-4d senti同=%-4d sarc同=%-4d %s" % (
        sc.split(':')[-2]+':'+sc.split(':')[-1], cid, plat, n, ss, cs,
        "<== 该批兜底" if (fallback and not small) else ("(小批同值, 不判)" if fallback else "")))
print("\n兜底批次数=%d (必须为 0；小批同值不计)" % bad)
```

判读：**批次条数 ≥ 20 且整批 `senti同=n 且 sarc同=n` = 该批走了关键词兜底，此题作废重跑。**
各批次都有不一致 = 真模型；小批次（< 20，如 1/2/5 条）同值是偶然撞值，单独列出、不判。
