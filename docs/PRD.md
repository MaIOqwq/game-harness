## 1. 背景与问题

游戏讨论高度分散在多个社区（NGA 版块、B 站视频/评论）。普通玩家想弄清一件事要跨平台翻几百条帖子：

- **实时问题**（"这版本主流配队怎么组""这次节奏是真的还是日常打架"）——等攻略站更新慢，社区当下一线讨论没人聚合。
- **旧事问题**（"上期活动什么评价""那个节奏是怎么起来的"）——人肉回溯费时，且容易只看到嗓门大的声音。
- **话里有话**（黑话、反串、阴阳）——直接搜关键词会被"带偏"，需要拆解语境。

已有的舆情**大屏**是"监测类"产物（看总量趋势），它不回答单点问题。本产品补的是"**问答类**"：给一个具体问题，交回一份**带证据链的答案**。

## 2. 目标与边界

**目标**：普通二游玩家、求职面试官都能跑通的问答 demo —— 我问、它取证、它给结论 + 出处。

**边界（刻意不做 / 阶段不做）**：

| 不做 | 原因 |
|---|---|
| 登录/账号体系、多租户 | 单用户 demo，不引复杂度 |
| 覆盖全平台 | 一期只 NGA + B 站两个社区；平台接入做成可扩展 |
| 攻略站/官方公告做权威源 | 答案是**社区口径**，不是权威口径；权威源是另一采集决策 |
| 训练通用大模型 | 推理用现成 LLM（选型 D2），只训一个窄任务小模型 |
| 舆情领域的全自动"带节奏溯源" | 舆情是旗舰纵深，只对**能接住的部分**承诺，其余明说不可靠 |

## 3. 用户与典型场景

**用户画像**：游戏玩家本人（自用 + 演示）、社区运营/竞品观察者、潜在 HR（看产品完成度与工程化）。

**两类问题分层（决定要不要上纵深手段）**：

- **① 通用中段**（量大，冷启动 + 搜索即可覆盖，几乎不加专用工具）：攻略 / 配队 / 强度平衡 / 值不值得玩 / 入坑回坑 / 机制玩法 / 剧情 lore / 近期动态。
  - 作答口径 = "社区当下怎么说、何时说的" + 引原文；爬虫是**活数据源**，新版本争论爬得到就是热乎的。
- **② 舆情硬尾**（量小但难，是护城河 / 纵深）：黑话解码（"膨胀神游"指谁）、反串/阴阳判定、自基线爆发判别（"这是节奏还是日常"）、"没节奏"也需要证据、谁在带节奏。
  - generic 搜索/RAG 干不了，需要专用 determiner；一期以软信号 + 人工可见为主（见 FR7 / NFR-精准）。

**诚实边界（产品铁律）**：攻略/配队答案是**社区当下说法**，不是攻略站权威——社区有争执、版本更新会滞后。答案必须 cite、标"这是社区当下说法，可能有滞后"。能答则答，不确定就明说。

**典型问句样例（脱敏，来自实录）**：

- 中段：*"鸣潮现在主流配队怎么组"*、*"绝区零值不值得回坑"*、*"这版本大家在聊什么"*
- 舆情纵深：*"最近这波是节奏还是日常打架"*、*"'膨胀神游你就玩吧角色巨保值'到底在说哪个游戏"*
- 回顾：*"上次那个限定池的风评最后咋样了"*

## 4. 功能需求（FR）

> 状态标记：`✅已实现` / `⏳待实现` / `⛔搁置`。每项给验收口径——面试与测试都按它验收。

### FR1 会话前台 — 双模式 + 平台比例旋钮自选 ⏳（部分✅）
- **需求**：网页聊天形态。左侧会话与历史，右侧聊天栏；聊天栏可内嵌图表（供数据展示）；用户发问前**显式选档**：`快速`（先给能看的初答）或 `精准`（深挖再答）。另有**平台比例旋钮**（可选，默认不显式动=均等）：单滑钮 0–100 控制 **NGA 占比%**，余量=bili —— 两端 = 单平台（0=只 bili / 100=只 NGA），中间 = 按比例偏向两侧取样本（软引导，±5 百分点内不强卡）；值随本次发问传给后端（映射 harness `nga_ratio`，语义 A 样本证据配比，正源 PLAN §10.12）。旋钮旁给一行抽样/偏置口径小字：动了旋钮，答案的"样本少/单平台"声明按所选平台如实出。会话历史支持单条删 /「清我全部」（防误删三闸 + 数据层分家，见 **FR9**）。
- **爬虫状态灯与登录态自助修复（09-12 拍，见 PLAN §10.31/§10.32）**：两个爬虫是**核心工具**（不装就没有问答），前端须给它们的健康状态**两个分开的灯** —— ①「服务在不在」（读爬虫服务 `GET /health` 的 `ok`）②「登录态有没有效」**从 `ok` 里拆出来单列**（现 `/health` 只回 `{ok, busy, queries_done, time}`，**尚无登录态字段，待加**）。灯亮红时给**自助修复入口**：bilibili 直接出二维码让用户扫自己的号（复用 `crawlers/bili/qr_login_once.py`：它已能存二维码 PNG + 落 flag 供轮询）；NGA 没有扫码态（论坛非 App，登录态 = 一份 cookie），给"更新 cookie"的引导与校验按钮。**硬要求：登录态无效时答案侧必须明说「本轮样本作废」**，不许把空结果说成"社区没讨论"（正对 §10.29 审计最重的一类错）。
- **部分✅（9/7）**：CLI 会话壳已落（`harness/runner/`：`Session.ask_turn()` + `/correct`）；本 FR 剩余 = 网页形态前台（待建）+ 上面这组状态灯/扫码面板。
- **验收**：输入任意中文问句 → 选定档位（可选拨旋钮）→ 得到带引用答案；拨到 100 时答案样本全来自 NGA 版块、拨到 0 时全来自 B 站、中心≈双平台现状；同一会话可追问；历史可回看。涉及数据时能看图表（折线/情感分布等）。**爬虫掉线或登录态失效时**，状态灯 5 秒内转红且给出修复入口；此时若强行发问，答案显式声明样本作废而非给"社区没讨论"。

### FR2 提问理解 — 冷启动 + 别名/黑话 ⏳（部分✅）
- **需求**：冷启动先判断这个问题社区是否可答、需要什么；用户黑话/别名能映射到游戏与关键词，防爬取跑偏（"三蹦子"→ 崩坏三；"膨胀神游"需语境解码）。
- **验收**：对"攻略配队"类问句不依赖预设题库也能自主开工（已实证）；黑话题能给出可溯源解码或明确放弃并说明。注册表一期先做最小可用。

### FR3 实时数据获取 — 真爬 + 门控 ✅
- **需求**：按需真爬 NGA + B 站当前数据（非存量库）；模型只见 `{查询词 + 游戏 + 平台}`，**数值参数不放给模型**（视频数/评论数/排序由引擎定，防 LLM 乱调）。
- **门控**：样本达标提前停（快速 120 / 精准 500）、爬轮预算强制停（3/5）、B 站两轮间隔（60s/120s）、平台冷却与断路器。
- **验收**：快速档一轮问答在合理时间（分钟级）内给出 ≥120 条双平台样本；限流时如实注明"样本偏少/单平台缺失"，不硬编。

### FR4 存档与检索 — 落档是副作用 ✅
- **需求**：每次真爬的**原文**自动落 L3 存档（append-only + 去重），这是引擎副作用，**不由模型决定存不存**；可检索历史话题，供"存档只答过去、不答现在"的边界用。
- **验收**：一次爬取后库中新增记录可查、可去重；回顾类问题能从存档检索并引原文（见 FR5 引用链）。

### FR5 作答与引用 — 诚实契约 ✅
- **需求**：答案由 LLM 在"本轮采到的证据原文"上合成，**逐条带 `[id=N]` 原文引用**；明说不确定性；末行给"结论："。图表类答案结论置顶。
- **验收**：抽查任意答案，`[id=N]` 都能对回存档原文；不确定处有明确表态而非含糊；"这是社区口径非权威"随答案可见。

### FR6 上下文管理 — 护栏优先，不折叠证据 ✅
- **需求**：单次问答内证据**保真不折叠不裁剪**（折叠会断引用链，架构上错）；每次真爬到的样本**全量进上下文**（09-12 起，不再按条数截断 —— 截断会把"没看到"说成"社区没有"，见 PLAN §10.33）；只设输入上限护栏 `IN_CEILING`（快速 160000 / 精准 320000，按模型窗口留足余量）在异常工具风暴时提前收口作答。省 token 的正解是少绕圈（轮数），不是截原文。
- **验收**：正常问答护栏休眠、证据完整；人为构造工具风暴时在护栏内收口作答而非爆上下文。

### FR7 舆情纵深 — 软信号**按需**打分（小模型=可选工具）+ 主链 LLM determiner ⏳（部分✅；口径 09-10 改写 + **09-12 改按需**，正源 PLAN §10.20/§10.21/§10.31）

- **需求（09-12 拍板后）**：
  - **小模型 StructBERT = 可选工具，不是必需**。检测到服务（`NLP_TOOL_URL` 可达）→ 用它（省 token + 图表有全量分）；**没有 → 主链 LLM 自己判情绪**。
  - **降级目标要改**：现状是服务不可达时**静默降级成关键词兜底**（只有 0/1 两档、无可疑度、跑批库里还看不出来），是三条路里最差的一条。**「关键词兜底」这条路废掉，降级目标改成「主链 LLM 自判」。**
  - **按需打分，不再每题都打**：判据放在已有**冷启动判断**那步（引擎侧多出一个布尔「这题要不要社区风向/情绪分布」，**不给模型加第四个工具**——工具面仍收窄为 `{crawl_nga, crawl_bili, search_archive}`）。要 → 对该题**已归档的全量样本**打分 + 出表；不要 → 完全不碰小模型，答案只引原文。
    - 判到"要"：问氛围 / 风评 / 口碑 / 为什么骂 / 社区怎么算这笔账
    - 判到"不要"：问数值 / 机制 / 攻略 / 入坑要多久 / 阵容（没有"分布"可言）
  - **软信号的**用法不变：每条样本的章随 crawl/search evidence 行喂主链 LLM 判向（sarcasm=1 的正面措辞如"策划真懂玩家"常是反讽，别当正面采信）；**软信号是初筛、可判错、不作硬判定闸、不追数值指标达标**。舆情纵深判定（黑话 referent/反串阴阳/自基线爆发）仍由**主链 LLM determiner** 承担：引原文、能判给证据、判不了明说。
  - **小模型那条线（labeler / gold 集 / 蒸馏 / 评测）作为毕设论文产物保留**，只是不再作运行期硬依赖。
  - **Why 改**：分发维度以前没算进去 —— 小模型要模型权重 + 深度学习依赖链，别人的机器装不动；且它不承担任何最终判定。顺带把 演示服务器 上"内存被回收杀掉→该题作废重跑"的事故面从"每题"缩到"只有风向题"。
- **验收**：① 不设 `NLP_TOOL_URL` 时答案质量与设了时**无实质差异**（对照实验：同题开/关各跑一遍）；② 风向类题出表、非风向类题不出表且不调用小模型；③ 图表口径一律 argmax 负面概率，不看分数符号；④ 反讽/硬尾题能给带证据的判定或明说判不了；⑤ 日志里**不得**再出现"度量降级 keyword"作为正常路径。

### FR8 图表呈现（嵌在聊天栏，**按需出**）⏳
- **需求**：触发图（热度折线 / 节奏时间轴 / 版本排期 / 对比）+ 固定图（情感分布 / 讨论度趋势），卡片式逐张出，**结论置顶**；共享时间轴可减出图量。
- **按需出（09-12 拍，见 FR7）**：情绪分布这类图表**只在冷启动判为"要看社区风向"时才出**，不是每题都出。前端必须能处理"这题没有情绪图"这种正常情况。
- **口径跟数据源走并显式标注**（这一条是数据精准度要求，不是可选装饰）：
  - 有小模型 → 「全量样本情绪分布」，样本量 = 该题归档条数
  - 无小模型 → 「**被引证证据**的情绪分布」，图上标注「样本 = 被引证据 N 条」，**不冒充满量**
  - 两种口径都要在图上写出来。理由：大模型只对**展示给它的十几条**（快速 5 / 精准 15）有判断，按全量口径画就是假的；而"被引证据"每条都带 `[id=N]`、都经主链真读过，比小模型全量分更可溯源。
- **验收**：问答结果里能嵌入对应图表并附说明；每张图**自带口径标注**（样本范围 + 条数）；非风向题不出情绪图不算失败。前端实现方案待拍（见 D7 与 §8 #1）。

### FR9 会话数据删除 —「清除对话记忆」防误删 ⏳（契约 09-09 定，未实现）
- **需求**：前端聊天栏/历史面板提供会话记录管理：单条删 / 清除单会话 /「清我全部」。清的是**该用户的会话层**（前端聊天历史 + 该用户 L1 StateCard/session_log/flow），**永不触碰证据层**（L3 `observation`/`crawl_run` 原文存档 + 报告）——它是跨会话共享、`[id=N]` 引用对回的正源；数据层分家正源 ARCHITECTURE §5.1，删除 API **单点实现**（scope+kind∈{conversation} 校验 + `--dry-run`），仓库无第二处散落 rm。
- **语义 = 软删优先**：删除第一步只打 tombstone（`deleted_at`，默认保留期 7 天）可一键恢复；物理清除是独立延迟任务（二期），**不放进按钮**。
- **防误删 UX 三闸**：①「清我全部」级 = type-to-confirm（输入将删条数/会话名），非普通一次"确定"；②删前 dry-run 明文显示将删范围/条数/时间窗 + **"证据库与历史答案引用不受影响"**；③共享部署默认只清**当前用户**，管理员级全库另有权限入口。
- **验收**：点「清我全部」→ 该用户会话列表清空，但任意历史答案的 `[id=N]` 仍能对回证据库原文；7 天内误删可恢复；删除动作在审计日志可查（谁/何时/scope/条数）。
- 打开项：保留期天数（默认 7）、按钮入口位置、「清我全部」确认粒度 —— 见 §8 #9。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 口径 |
|---|---|---|
| NFR-精准 | 数据精准度是**最高约束** | 一切数字图表用 argmax 负面概率口径，严禁看分数符号；数字可溯源 |
| NFR-诚实 | 不确定就明说，不编造 | cite、社区口径声明、"没证据/判不了"合法输出 |
| NFR-成本 | token 与算力可控 | 双档采样上限、软信号预筛减少 judge 调用、窄工具面防跑偏；费用以模型官方计费为准 |
| NFR-性能 | 快速档分钟级出初答 | 单轮门控保证不无限爬；live 标定见验收（D 档间隔为 B 站风控） |
| NFR-合规 | 凭证零泄露、可去敏发布 | 明文 cookie/token 绝不落仓库/日志；bili 登录态只在服务器持有；GitHub 发布物含文档、不含 vendor 源码树（见 D9） |
| NFR-可演示 | 本地零依赖可跑 | 标准库为主、无构建步骤；断网有兜底（mock 数据源）不白屏 |

## 6. 数据需求

- **输入**：中文问句 + 用户自选档位（快速/精准）+ **平台比例旋钮（可选，NGA 占比 0–100%，默认 50=双平台均等≈现状）**。模型侧工具入参白名单：`{query, game}`×2（crawl_nga / crawl_bili 各自固定一平台，09-08 起不再暴露 platform 参数给模型）/ `{query, game, platform?, as_of}`（search_archive）。旋钮 → harness `nga_ratio`：单标量 NGA 占比，余量=bili；100=只 NGA / 0=只 bili（端点硬压另一边）；语义 A=样本证据配比，内部 1–99 走**软引导**：每轮算本 ask 两平台累计新增占比，偏离目标 >RATIO_TOL=5 个百分点且欠配边未熔断/冷却时才提示模型下轮优先补那一边——只提示不改调度，模型仍有 final say（option-1，±5 可接受）；熔断/冷却闸门永远优先于比例（09-09，正源 PLAN §10.12 + §10.14）。
- **输出**：结论 + 证据引用 `[id=N]` + 可选的图 + 抽样/偏置声明（样本少、单平台缺失等如实注）。
- **核心常量（代码正源，防口径漂移）**：

| 常量 | 快速 | 精准 |
